# Governed Frontier-Model Candidate Intake

Status: PREPARATION ONLY. Discovery or registration MUST NOT make a model production-routable.

## Candidate lifecycle
1. discover model/provider announcement or catalog entry
2. verify canonical provider identifier and availability
3. capture dated source evidence
4. create candidate metadata only
5. run reproducible evaluations
6. attach Security/Governance/Financial review evidence
7. require explicit human promotion decision
8. only then become eligible for governed routing

## Required candidate metadata
- provider
- canonical model ID
- release/availability date
- modalities
- context/output limits
- tool/function capability
- pricing and quota source
- data-handling/retention notes
- region/availability constraints
- capability-risk tags, including cyber capability where applicable
- evaluation status
- approval status
- provenance/source URLs and retrieval timestamps

## Evaluation suite
- coding correctness
- reasoning reliability
- evidence/citation discipline
- tool-use boundary adherence
- prompt-injection resistance
- cyber capability/risk
- latency
- cost
- structured-output conformance
- Stone Passport/capability-ceiling compliance

## Safety invariant
Unknown, incomplete, unverified, or newly detected models remain candidate-only and cannot receive production traffic.

## Approval
Promotion requires Governance + Security + Financial + Human approval. Production rollout additionally requires Production approval.
